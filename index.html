Methodology & hardware

Runner environment

What each suite measures

  • Writers: Compiles public Geofabrik .osm.pbf files into GOL 2.0 databases (1 & 4 CPUs, warm input), measuring wall time, peak RSS, and file size while verifying output feature equivalence.
  • Scale: Replays the same 5-step interactive map-editor viewport session per city (open streets w[highway], amenities n[amenity], cafés *[amenity=cafe], pan east, zoom into crossings n[highway=crossing]) across datasets from 1 MiB (Monaco) to 3.6 GiB (UK) to show how query latency scales with total database size (1 CPU, warm cache).
  • CLI exports: Fresh-process counts and csv, geojson, and geojsonl exports over a Leeds bounding box on the 3.63 GiB UK GOL (2 CPUs), checking decoded output equivalence.
  • UK applications: Ten realistic multi-step OpenStreetMap application replays against the 3.63 GiB UK GOL (1 CPU), verifying identical digests across engines.
  • File generator. The same reader runs on GeoDesk-built and Regol-built files from one UK PBF. Each corpus round sums identical verified queries. Application timings include opens and preserve the order of the original workflow. Tagged releases add a cold café query on evicted file copies and fresh-process Leeds CLI exports. Positive savings mean less time on the Regol-built file. File digests and excluded cases are in the run data.
  • UK corpus (524 queries): Broad 524-case UK query corpus aggregated into three verified cohorts—identity streams, tag decoding, and geometry assembly (1 CPU, warm cache).

Processes are pinned with Linux taskset, arms rotate in Williams order, and every timed output is verified outside the timer. Harness source: github.com/regol-gis/gol-bench.
